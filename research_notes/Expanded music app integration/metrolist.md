## 1. What is actually implemented?

### Takeaway

Metrolist is a substantial multiplatform music application. Its most valuable additions for this project are library portability, recovery, download reliability, editable lyrics, and account state handling. Its Android equalizer is not a replacement for our native high-resolution engine.

The version catalog pins AGP 9.5.1, Kotlin 2.4.21, Compose 1.13.0-beta02, Media3 1.12.0-alpha02 and Room 3.0.3. These are the snapshot's declarations, not independently verified availability or compatibility. ### Inferences

A practical sequence is (1) stabilize the actual BitChord base and native-engine boundary, (2) library import/backup and editable lyrics, (3) download recovery and account/outbox reliability, then (4) optional recognition/remote features. StaaaaandBy remains a display consuming common playback state. None of these features requires replacing BitChord with Metrolist or migrating the whole project to KMP. Where BitChord already implements a feature, compare the failure behavior and tests before adding donor code; presence in two projects is not itself a reason to keep two implementations.

## 3. What blocks integration and what tests must pass?

### Takeaway

The main blocker is coupling: large donor modules carry their own database, global state, DI, providers and toolchain. Extract contracts and keep one owner for playback, library identity and settings. Use executable failure tests before device acceptance.

### Cited findings

- The pinned toolchain includes alpha/beta dependencies, while shared code is tied to Room3 and KMP platform implementations. Copying a module wholesale would impose unrelated build decisions. [Catalog](<C:/Users/SDK/Downloads/Cubic-Music-main/Metrolist-main/gradle/libs.versions.toml:2>), [shared build](<C:/Users/SDK/Downloads/Cubic-Music-main/Metrolist-main/shared/build.gradle.kts:1>)
- Source includes focused tests for client health, playback failure/cooldown, network/resource handling and romanization, but test files were only inventoried and not executed. These should inform a bounded extraction, not be counted as passing verification. [Client health test](<C:/Users/SDK/Downloads/Cubic-Music-main/Metrolist-main/shared/src/commonTest/kotlin/com/metrolist/shared/youtube/strategy/ClientHealthTrackerTest.kt:1>), [failure reporting test](<C:/Users/SDK/Downloads/Cubic-Music-main/Metrolist-main/shared/src/commonTest/kotlin/com/metrolist/shared/youtube/playback/PlaybackFailureReportingTest.kt:1>), [Mandarin test](<C:/Users/SDK/Downloads/Cubic-Music-main/Metrolist-main/shared/src/jvmSharedTest/kotlin/com/metrolist/shared/api/lyrics/romanizer/MandarinRomanizerTest.kt:1>)

### Inferences

Required gates for selected modules:

1. **Import and restore:** real fixtures from each selected family; preserve playlist order, duplicates and local ownership; unknown/newer schemas rejected without altering the live library; malformed/oversized/path-traversal archives rejected; interrupted restore leaves a recoverable database; integrity and foreign keys checked. Never silently match a different remaster or recording merely because a title resembles it.
2. **Lyrics:** fetched lyrics cannot overwrite user edits or drafts; cancellation cannot write an older result over a newer edit; offsets survive restart and track switches; Unicode and word timings survive parsing/export; negative cache expires; translation caches invalidate when source/config changes. Generated translations must not be presented as provider-authored original timing.
3. **Downloads:** invalid Content-Range, missing length, HTTP200 on nonzero ranges, redirects, truncation, expired URLs, storage exhaustion, cancellation and process death tested. Publish a file only after completeness validation; failed state persistence must retain the newest pending queue. Limit parallelism and memory under device/network pressure.
4. **Accounts and outbox:** plaintext migration interrupted at each step; missing/invalidated Keystore keys; backup/restore exclusions; no credential content in diagnostics; logout/account switching cannot submit another account's pending events; retries do not duplicate accepted submissions uncontrollably.
5. **Playback/remote:** one MediaSession owner, truthful playback state and queue identity; audio focus, calls, Bluetooth/USB transitions, foreground lifecycle and reconnects on S24+. Cast/remote receivers do not automatically inherit local DSP or bit-perfect guarantees. Native PCM formats, bypass, rate changes and DSP ordering remain governed by our engine gates.
6. **Release provenance:** record exact copied files, source revision and notices; separately inventory dependencies, submodules, lyric/romanization resources and account/provider use. The user's permission statement is accepted as context; permission scope and distribution obligations must be recorded, not assumed erased by later improvements.

Provider-specific recovery should be isolated behind replaceable resolvers. Source code that currently reaches an unofficial endpoint is not evidence that the endpoint is durable or appropriate for the intended release. No challenge-bypass integration is recommended. Recognition/remote features require their own concrete consent, authorization and security checks when selected; they need not delay local-library and lyrics work.

### Gaps

No app changes were made, no dependency resolution was attempted, and no merge readiness claim is made. Exact port size, provider availability, whole-app license closure, runtime battery/memory cost, USB audio behavior and Play distribution eligibility require later targeted validation. This report intentionally leaves broad optional features outside the first implementation milestone.
