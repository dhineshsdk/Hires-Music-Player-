# Cubic Music source review — 16 November 2026

Read-only review of the supplied snapshot. No donor build scripts, binaries, tests, network clients or application were executed. README claims are separated from traced implementation. This is a substantial integration review, not a verified build or exhaustive audit of every screen. The accepted destination remains the full BitChord application with its actual UI; the existing native DSP becomes Audio Lab and StaaaaandBy supplies the immersive display.

## 1. What is actually implemented in this snapshot?

### Takeaway

Cubic is useful mainly for lyrics tools, listening-history presentation and CSV portability. It is a large existing application with its own database, services, providers and player. Copying the entire app would create competing foundations.

### Cited findings

- The build includes Android and desktop source sets, two Innertube integrations, LRCLIB, Kugou, Better Lyrics, Piped and Invidious. Its Java Innertube module points to knighthat/innertube-java. These are real build dependencies, not a feature checklist. ## 2. What should be reused in the full BitChord base?

### Takeaway

Use Cubic as a donor of small, testable tools. Reuse code where the data contract is clear, and adapt it to BitChord's source IDs, playback position, library and history rather than importing Cubic's global database/player service.

### Cited findings

- The lyrics implementation mixes parser/rendering with global preferences, provider calls, translation state and player state inside a very large screen; its useful pure timing functions begin near line 226 and the editing UI near line 1290. This supports extraction rather than a whole-screen replacement. [lyrics helper boundary](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/composeApp/src/androidMain/kotlin/app/it/fast4x/rimusic/ui/screens/player/Lyrics.kt:226); [editing boundary](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/composeApp/src/androidMain/kotlin/app/it/fast4x/rimusic/ui/screens/player/Lyrics.kt:1290).
- Rewind's history access is through Cubic's global Database, so its calculations need a repository adapter. A year-range query should replace loading the full listening history. [database coupling](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/composeApp/src/androidMain/kotlin/app/it/fast4x/rimusic/ui/screens/rewind/RewindDataFetcher.kt:119).
- CSV search converts external catalog entries into Innertube identities. A Spotify ID and our local file identity are not interchangeable; the code's first-result behavior must be changed before automatic library assignment. [matching behavior](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/composeApp/src/androidMain/kotlin/app/kreate/android/me/knighthat/component/tab/ImportSongsFromCSV.kt:290); [Spotify handling](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/composeApp/src/androidMain/kotlin/app/kreate/android/me/knighthat/component/tab/ImportSongsFromCSV.kt:407).
- The source contains its own queue deletion/reinsertion on persistence, reinforcing that importing the service would introduce a second authority. [queue authority](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/composeApp/src/androidMain/kotlin/app/it/fast4x/rimusic/service/modern/PlayerServiceModern.kt:3271).

### Inferences

Recommended sequence, after confirming donor eligibility:

1. **Contracts and baseline:** keep BitChord UI, one playback/queue authority, existing Audio Lab/native engine boundary. Inventory BitChord's already-working equivalents first. Define stable track/source IDs, lyric granularity, playback clock and listening-event contracts. Copy selected files into an isolated feature branch with notices.
2. **Lyrics tools:** port clean timing parser utilities and useful editor/offset actions; plug them into BitChord's existing lyrics view. Preserve plain/line/word granularity explicitly. True word highlighting only for provider-authored word timestamps; never synthesize word or syllable timestamps from line duration. Validate malformed LRC, repeated words, RTL/CJK, offsets, instrumental lines, seek/backward jumps and provider fallback.
3. **History and Rewind:** use real observed playback durations, pause/seek/repeat semantics and explicit count thresholds; port recap cards after calculations are tested. Use bounded database queries and a defined timezone/year boundary. Empty history gets an honest empty state.
4. **CSV portability:** reuse CSV data/schema handling and progress presentation. Export original source IDs alongside metadata. Show a preview and distinguish exact identity, probable match, ambiguous result and missing track. Preserve input order/duplicates according to user choice. Never silently substitute the first live/remastered/video result.
5. **Downloads/cache:** add a simple storage screen, retry/delete and cache-versus-pinned-download separation. Verify scoped-storage behavior and cancellation first. Implement and test actual integrity checks before presenting a corrupt-download category as reliable.
6. **Recognition later:** consider Cubic's capture/result UX; compare with the LastWave review and choose one reliable implementation. Resolve the native fingerprint wrapper and service terms, or use the official provider SDK. No recognition provider is required to launch the base.

Crossfade, automatic gain, EQ and visual meters must obey our engine contracts. A crossfade changes samples and cannot be displayed as untouched bit-perfect playback. Cubic's player does not replace the existing native DSP or USB plan.

### Gaps

BitChord feature-by-feature duplication must be checked against its exact imported snapshot before selecting donor files. Reuse estimates remain provisional until a small isolated donor build/test establishes closure. No recommendation to merge databases, transfer credentials or inherit Cubic's entire settings tree.

## 3. What coupling, readiness and validation gaps affect integration?

### Takeaway

Donor eligibility is the first gate. Missing source references, opaque recognition assets, parallel database architectures and untested migrations make a whole-app transplant risky; these do not prevent small verified feature ports.

### Cited findings

- Android's active Room database is version 27 with registered migration steps. A separate commonMain MusicDatabase is version 23 and has its addMigrations call commented. Treat these as different architectures; importing both would not create a unified library. [Android schema and migrations](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/composeApp/src/androidMain/kotlin/app/it/fast4x/rimusic/Database.kt:401); [Android migration registration](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/composeApp/src/androidMain/kotlin/app/it/fast4x/rimusic/Database.kt:446); [common database version](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/composeApp/src/commonMain/kotlin/database/MusicDatabase.kt:50); [common migration comment](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/composeApp/src/commonMain/kotlin/database/MusicDatabase.kt:109).
- The catalog pins AGP 9.4.1, Kotlin 2.4.20, Room 2.7.2 and Media3 1.8.0. These are source declarations, not verified published/resolved versions. Desktop-specific files are excluded, and desktop dependencies include JavaFX win artifacts. Do not pull the whole build graph into BitChord. [declared versions](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/gradle/libs.versions.toml:4); [desktop exclusions/dependencies](C:/Users/SDK/Downloads/Cubic-Music-main/Cubic-Music-main/composeApp/build.gradle.kts:64).

Four ABI folders contain libshazam_signature_jni.so, and Gradle includes androidMain/jniLibs. This establishes packaged native assets, not the missing wrapper's provenance or source closure. No environment/local credential file was opened for this review. ### Inferences

Before a port is called ready:

- Establish a reproducible donor build in isolation with pinned artifacts and a recorded toolchain; resolve missing source references without assuming they are compiler errors from static inspection alone. Do not run opaque donor setup scripts.
- Add focused parser/calculation/import tests around extracted utilities. Primary app-tree test inventory did not identify tests covering these candidate features; module/network fixtures are not a substitute for app integration checks.
- Verify schema adapter and upgrade behavior against real copies of the destination database. Keep automatic rollback/migration handling outside the audio callback.
- Keep networking/account/provider tokens out of audio processing and logs. Bound microphone capture duration and memory, release on cancel/error/background, and test denied permission. Cubic's growing full-buffer copies warrant redesign before reuse.
- For native recognition assets, locate source/build instructions and licence notices, and validate ABI/page-size compatibility before distribution. No opaque .so was loaded in this review.
- Test offline/online transitions, cancellation, partial files, duplicate IDs, unavailable tracks, process death and resumed queue behavior. A Download.STATE_COMPLETED flag alone is not an audio checksum.
- Preserve legal notices and distinguish approved feature reuse from authorization of third-party services. Existing user permission to reuse BitChord does not settle provenance of unrelated binaries from new donors.

### Gaps

This was static source research only. No Gradle resolution, compile, lint, device playback, migration run, waveform measurement or provider availability check was performed. External SDK/service behavior and current store requirements must be verified at implementation/release time. The repository may contain generated/private pieces absent from this snapshot; the unresolved helper findings identify investigation gates, not proven build failures.
