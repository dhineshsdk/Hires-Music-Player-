# Target app architecture and integration readiness

## What does the actual target already contain?

### Takeaway
The target is `D:/MusicPlayer-Projects/Music-Player`, not the older active C: worktree. It already contains a native engine, Media3 session, queue controls, crossfade settings, three DAP skins, Drive helper code, USB exclusive code, DSP stages and telemetry. Preserve those foundations and add the donor projects' useful experiences through adapters; do not replace the engine or plan existing features as new work.

### Cited Findings
- `NativeEnginePlayer` is a Media3 `SimpleBasePlayer` backed by `NativeAudioEngine`; `DeterministicAudioService` owns exactly one player and MediaSession, supplies notification/lock-screen/headset control, and manages a playback wake lock. This is the correct control surface for an integrated dock screen, so listening to all other apps' notifications is unnecessary for our own playback. [Player](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/playback/NativeEnginePlayer.kt:45), [service](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/service/DeterministicAudioService.kt:53).
- Repository exposes current-track state, local library, DSP state, queue, USB state and telemetry. It polls position at 200ms and native telemetry approximately 30Hz while playing. These are existing seams for lyrics and a dock screen, although position should be published as an anchored playback clock rather than forcing frame-rate repository updates. [Repository](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/state/AudioEngineStateRepository.kt:38), [player ticker](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/playback/NativeEnginePlayer.kt:112).
- `DapModeScreen` already switches Liquid/Deck/Afterglow skins and receives real engine telemetry; it is entered separately from the main five-tab shell. It supports swipe-down/back/exit. Deck uses channel RMS values when telemetry says levels exist. There is no reason to invent an unrelated sixth permanent tab for dock mode. [DAP screen](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/ui/DapModeScreen.kt:73), [looks](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/ui/theme/Look.kt:10).
- Queue sheet and queue-item model are implemented. Repository can play/remove an item and clear the queue. Need to inspect/extend robust reorder, play-next/add-to-end, save/restore and persistent playlist/history semantics instead of merely adding a duplicate queue UI. [Queue UI](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/ui/QueueSheet.kt), [queue state](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/state/AudioEngineStateRepository.kt:266).
- Crossfade is already configurable from 1–12 seconds with linear/equal-power/logarithmic curves, defaults off, and stores album preferences. Native player disables fades whenever its own same-album check returns true, even though settings offer `crossfadeSameAlbum`; this interaction needs reconciliation before adding Automix. Crossfade changes samples, so it must never be labelled bit-exact. [Settings](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/playback/TransitionSettings.kt:24), [preload decision](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/playback/NativeEnginePlayer.kt:490), [native receipt mixed check](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/core/PlaybackEngine.cpp:1948).
- Local library is MediaStore-based, currently a list of `LibraryTrack` grouped into albums; it includes DSD scanning and header duration fallback for ALAC/M4A. Its `isHiRes` currently guesses yes for unknown-rate/depth FLAC/WAV/AIFF, so a richer feature catalogue should distinguish confirmed format from container-only metadata. [Library metadata](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/MusicLibrary.kt:10), [hi-res classification](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/MusicLibrary.kt:51).
- Source supports WAV-family, FLAC, DSF/DFF and optional dynamic FFmpeg. FFmpeg decoder only compiles when headers/shared objects exist; otherwise build succeeds without those formats. CMake fetches FLAC 1.4.3 and Oboe 1.9.0; libsoxr is a shared library. Format capability UI should reflect actual packaged support. [CMake](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/CMakeLists.txt:78).

### Inferences
- The app's strongest identity is a native audio workstation with a rich presentation layer. BitChord supplies interaction/catalogue patterns; StaaaaandBy supplies presentation and lifecycle patterns. The donors should not become parallel playback engines.
- Main tabs remain Playing, Library, Path, DSP, Output; lyrics are a Playing expansion, downloads/playlists are Library sections, dock is a fullscreen mode reusing existing DAP entry point, provider configuration belongs in settings reachable from Library/Output.
- Suggest three presentation modes around the same live session: Focus (existing luxury player), Lyrics (readable synced text), Dock (landscape artwork/clock or lyric animation). Existing Deck/Afterglow/Liquid skins continue to apply without forcing a new global visual identity.

- No build, lint, host tests, CI run or physical S24+ test was executed because the user expressly requested planning only. Source presence is not evidence of runtime correctness or completed phase gates.
- Exact target commit could not be established: `git -C D:/MusicPlayer-Projects/Music-Player ...` returned permission denied; ordinary source reads succeeded. Existing C: worktree HEAD is `ba0b047ffe4906f9b574a8503e816ac5e2fbf761`. Before implementation, reconcile snapshots without overwriting user's newer D: work.

## What must be fixed or clarified before broad integration?

### Takeaway
There are meaningful foundations, but several visible UI claims outrun current wiring or the approved architecture. Make an initial source-and-device baseline gate part of the implementation plan; do not assume importing donor features will fix these issues.

### Cited Findings
- **Network permission:** target main manifest does not declare `android.permission.INTERNET`, despite Drive network code. Its MediaSessionService is correctly `foregroundServiceType="mediaPlayback"`. Main manifest absence is confirmed; inspect merged manifest before declaring installed-APK behavior. [Manifest](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/AndroidManifest.xml:4).
- **Drive is currently full-download-before-play in the UI:** `playDriveFile` constructs a local cache URI, downloads using `NextTrackPrefetcher.prefetch`, and invokes playback only after completion (or when the entire local file already exists at expected size). Status says HTTP Range streaming, but that UI flow does not start native decode during download. [Drive flow](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/LibraryScreen.kt:473).
- **Remote callbacks exist but the normal queue opens descriptors:** `NativeAudioEngine.openCallbacks/setNextCallbacks` and `RemoteByteSource` exist, while `NativeEnginePlayer.openCurrent` and `preloadNext` call `openFd` then `engine.open/setNext`. Need a proper source resolver rather than attaching more special URI branches to the player. [Callback wrapper](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/playback/NativeAudioEngine.kt:41), [source interface](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/source/RemoteByteSource.kt:13), [current open](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/playback/NativeEnginePlayer.kt:395), [next open](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/playback/NativeEnginePlayer.kt:474).
- **Drive auth/index limitations:** UI accepts an access token into SharedPreferences, with no full OAuth/refresh flow. `GoogleDriveClient.openByteSource` ignores force-refresh and returns the same token; listing asks for pageSize=100 but does not request or follow nextPageToken; indexing FLAC reads first 64KB. These are source-observed limits, not a finished robust multi-source library. [UI token](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/LibraryScreen.kt:391), [token provider](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/drive/GoogleDriveClient.kt:43), [list request](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/drive/GoogleDriveClient.kt:64), [head indexing](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/drive/GoogleDriveClient.kt:147).
- **Database gap:** seek metadata cache is SQLiteOpenHelper, not Room, and `onUpgrade` drops/recreates tables. Approved rules require Room-cached seek tables. Treat migration/preservation as work; do not drop existing data while introducing playlists/history/offline state. [Cache](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/cache/SeekTableCache.kt:165).
- **Telegram is a seam rather than a complete account integration:** `TelegramFileApi` is an interface with `sizeOf`, `ensureRange` and cancel, consumed by `TelegramByteSource`; no concrete TDLib account/auth/channel flow appeared in inspected app sources. [Telegram adapter](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/source/TelegramByteSource.kt:12).
- **Receipt honesty gap:** `SignalPathState.build` can infer VERIFIED from Output B selection or OS_CONFIRMED from Output A bit-perfect selection when actual telemetry has no receipt grade. `selectUsbOutput` also marks confirmed on successful selector return. These should become requested/active/verified states; do not equate requested output with proven sample delivery. [Fallback grade](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/model/SignalPathState.kt:483), [USB route](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/playback/NativeEnginePlayer.kt:450).
- **Not an end-to-end hardware receipt:** native hashes are taken on rendered PCM buffers before external DAC conversion; they are useful internal sample receipts, but do not independently measure the DAC's received USB bytes or analog result. Path UI currently says hardware receipt hashes match. Wording and validation scope must be corrected. [Render hash](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/core/PlaybackEngine.cpp:1682), [UI copy](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/ui/PathScreen.kt:88).
- **DSP precision gap:** engine does `ToStereoFloat(... floatScratch_)`, calls ProcessPre/EQ/ProcessConvolution/ProcessPost on `float*`, and converts HRC_SAMPLE_F32 to output. Several calculations are double internally, but interstage storage is float32. This does not implement the approved all-stage 64-bit float signal path. Keep this as an explicit native-engine work item with measurement gates, rather than advertising precision from class names. [Render chain](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/core/PlaybackEngine.cpp:1667), [chain signature](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/dsp/DspChain.hpp:243).
- **GPU callback wait risk:** RenderSegment calls ProcessConvolution; DspChain calls convolver.Process; convolver.Process calls ProcessBlockVk when available; ProcessBlockVk waits on `vkWaitForFences` with a 20ms timeout. That is a synchronous wait in the render call chain, at odds with deterministic low-latency callback goals. Actual deadline misses are not measured here. Plan asynchronous worker/double buffering with bounded ready-result consumption and a measured CPU fallback, not a busy or blocking render wait. [Call site](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/core/PlaybackEngine.cpp:1672), [chain](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/dsp/DspChain.hpp:244), [GPU dispatch](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/dsp/VulkanConvolver.cpp:493), [fence wait](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/dsp/VulkanConvolver.cpp:819).
- **CI gate gap:** workflow has many native sanitizer tests and debug assembly, but no explicit `testDebugUnitTest` or `lint` task. Kotlin test files exist for remote sources, DSP/transition settings and telemetry honesty. Need explicitly executed coverage, not just files. [CI](D:/MusicPlayer-Projects/Music-Player/.github/workflows/android.yml), [tests](D:/MusicPlayer-Projects/Music-Player/src/app/src/test/kotlin/com/audiophile/engine).
- **Release baseline:** app targets/compiles API34 and NDK26.3 with AGP8.5.2. Current official Play documentation says phone new apps/updates must target API36 from Aug31 2026, with extension to Nov1 2026. As of user date Nov15 2026, API34 is not a release-ready baseline. [App build](D:/MusicPlayer-Projects/Music-Player/src/app/build.gradle.kts:8), [official target requirement](https://developer.android.com/google/play/requirements/target-sdk).
- **16KB support:** own engine includes max-page-size linker flag, but all shared libraries and APK/AAB packaging must be checked, including FFmpeg, libsoxr and libc++_shared. Official guide recommends AGP8.5.1+ and NDKr28+ for default support with compatible dependencies; it currently states updates must meet support by Feb1 2027. Do not repeat older deadline text from memory. [CMake link options](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/CMakeLists.txt), [official page-size guide](https://developer.android.com/guide/practices/page-sizes).
- **Android14 capability is optional:** AOSP confirms preferred mixer attributes allow query/configuration for USB, but the BIT_PERFECT attribute is optional and depends on AIDL HAL support. Check actual capability per phone/DAC/firmware and retain supported fallbacks; don't promise all Android14 USB routes are bit-perfect. [AOSP](https://source.android.com/docs/core/audio/preferred-mixer-attr).

### Inferences
- Do not present donor UI richness as evidence that native correctness is solved. Build data and playback contracts around truthful unavailable/loading/active/verified states.
- Reference PDFs/older blueprint include claims not safe to adopt literally: SCHED_FIFO suggestions in research1 p31 conflict with approved no-FIFO rule; RT PDF p5 pins USB pump 0x180 while approved rules say 0x70; prefaulting/foreground service does not guarantee permanently resident memory or TLB locking; old Apple protected-audio DSP ideas are explicitly superseded by approved no-DRM rule. Documentation should reconcile these in a later authorized change.
- Files and APK descriptions must distinguish bit-exact to our output buffer, OS-confirmed route, and independently measured endpoint behavior. They cannot certify that a file is genuinely native hi-res simply because low bits or ultrasonics are present/absent.

### Gaps
- Full mathematical audit of native tube/tape/R2R/ISO226 processing, USB descriptor quirk correctness, Vulkan shader correctness and physical S24+ characteristics is outside this source review. Do not assert success/failure of device gates.
- No exact overall feature estimate is defensible until baseline, product priority, source policy and license approach are chosen. Use relative complexity/dependencies rather than invented weeks.

## What implementation plan best combines both donors with this app?

### Takeaway
Use one source identity, one queue, one native playback engine and one playback clock, then layer library/lyrics/dock experiences on top. Stabilize truthfulness and source plumbing first; deliver a local/offline polished experience before adding provider-dependent/social/other-device scope.

### Cited Findings
- Existing `RemoteByteSource` explicitly permits network blocking only on decoder threads and has random-access/close ownership contracts; KotlinByteSource maps this into native callbacks. It is the appropriate ingestion seam. [Source contract](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/source/RemoteByteSource.kt:5), [native bridge](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/jni/KotlinByteSource.cpp).
- Existing next-track prefetch uses .part, size/checksum validation and rename; failures/cancellation clean staging. Evolve this into a download job repository without creating a separate player. [Prefetcher](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/source/NextTrackPrefetcher.kt:9).
- SafeMoveToDrive already requires checksum verification and explicit deletion consent. But current UI copies the picked input into a cache temp file and passes that temp file to the move routine, so a 'move' success deletes the temp copy rather than the original user-selected source. Product copy and actual URI ownership need redesign. [Move safety](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/source/SafeMoveToDrive.kt:26), [UI temp copy](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/library/LibraryScreen.kt:423).
- Existing exact same-format/gapless engine and crossfade receipts supply a base for feature policy; crossfade intentionally changes samples and native receipts account for this. [Engine](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/cpp/core/PlaybackEngine.cpp:1948), [settings](D:/MusicPlayer-Projects/Music-Player/src/app/src/main/kotlin/com/audiophile/engine/playback/TransitionSettings.kt:20).

### Inferences
Proposed phases (product slices; they do not replace approved engine phases 0–7):

1. **Baseline and ownership — prerequisite.** Establish target snapshot, preserve current D: work, inventory build/native dependencies and per-file donor provenance. Run current CI/host/Kotlin/lint and S24+ audio regressions only after build authorization. Record feature capabilities rather than TODO comments. Fix capability/receipt honesty, decide required native precision/RT fixes. Exit: reproducible baseline, no unsupported 'verified' badges, no new regressions.
2. **Unified media foundation — medium/large.** Stable TrackId distinct from source URL; source-specific versions linked by exact metadata/fingerprint only with review; queue entries reference TrackId+chosen SourceId; persistent playlist/favorite/history/offline tables with migration. SourceResolver opens FD or RemoteByteSource and carries capabilities (seek/range/download/artwork/lyrics/auth/official-player-only), errors and cancellation. Do not accidentally match clean/explicit, remaster/live versions merely by title. Exit: local/SAF files survive restart, queue persistence correct, no duplicate player, migration tests.
3. **Lyrics foundation — medium.** Embedded or user-supplied LRC first, then explicitly permitted opt-in provider. Shared immutable LyricsDocument with line/word timings, source attribution/license/cached version and no-lyrics/error states. Clock anchor includes media identity, elapsedRealtime, source position, speed, playing/buffering status and output latency when actually known. Extrapolate display, reset on seek/track/speed change; do not derive lyrics timing from VU/audio render. Exit: seeks/pauses/transitions/missing lyrics/offline cache correct; animations do not change audio hashes.
4. **Dock mode — medium.** Extend existing DAP fullscreen entry with a dock presentation: slit-scan artwork, restrained clock, title/artist/real format/route, optional lyrics; landscape and portrait. Manually opened mode first. Brightness, motion, pixel-shift, timeout/exit, battery/thermal settings; reduce refresh or suspend web page when paused/hidden/hot. Artwork never pretends to be an audio meter. Use own Media3 session and route controls. Exit: lifecycle/config changes no leak; night setting respects system; no audible glitches under measured GPU/UI load. Automated charging/lock-screen start is separate platform research gate, not copied wholesale.
5. **Library and offline collection — medium/large.** Albums/artists/search/folders/playlists/favorites/history, metadata provenance, richer queue editing, sleep timer, local lyrics/art cache. Download manager uses app-scoped destinations, durable jobs, auth refresh, cancellation/retry/quota and .part finalization; WiFi/mobile policy; independent next-audio/next-art/next-lyrics prefetch. Exit: process death/network loss/restart/cache eviction never destroys pinned files or corrupts queue.
6. **Cloud/provider integration — large, per-provider.** Finish Drive OAuth, pagination/head-tail indexing/native callback range streaming first; then concrete TDLib integration when that engine phase allows. SMB is a plausible personal-library addition. Spotify/Apple initially metadata/playlist import and matching to user's own media with visible unresolved matches. Official SDK players remain separate transports for protected playback and honestly disable native DSP/bit-perfect claims. Provider-specific permission/legal eligibility is data, not a global 'can download anything' assumption. Exit: seek costs/cancellation/token expiry/source origin all covered; no protected audio pushed into native engine.
7. **Optional advanced experiences — separate roadmap.** Art-driven accents constrained to existing typography/contrast and gold/amber roles; animated canvas opt-in/local/licensed assets; Last.fm/ListenBrainz opt-in with privacy controls; Cast/Auto/TV/Wear/desktop/web/party later as independently scoped clients. Automix/tempo/silence skipping are explicit processed-listening modes, separate from untouched mode and after core RT gates. Native USB/DSP remains governed by existing phases, not replaced with donor transport.

Brainstorming worth carrying into product design:
- **Listening scenes:** Focus, Lyrics, Desk/Dock, Night reuse one queue/session. Optional per-output remembered scene, but do not auto-change gain/DSP without clear user setting.
- **Music as artwork:** progress-driven slit-scan cover, selectable quiet vinyl/Deck skin, typography matching current gold/amber identity. Offer a static low-power mode and large-text view; music controls remain accessible even with animation disabled.
- **Honest quality card:** source's decoded format, actual output format, active processing, internal receipt and route capability shown separately. A plain explanation for why exact output is unavailable is more valuable than a universal green badge.
- **Versions-aware collection:** local/Drive/Telegram copies linked without silently substituting another master; prefer offline copy when identical identity/version, preserve user's choice, show why a source is selected.
- **Queue intelligence:** protect live/concept album boundaries, group upcoming items by album, allow 'finish this album then sleep', cache the exact next version and its lyrics/art.
- **Private by default:** embedded/local lyrics/art first; provider lookup opt-in states what track metadata leaves device; scrobbling/history retention and lock-screen title visibility independent preferences.
- **Performance budget:** no network/file/db work in audio callback, lyric/cover processing on ordinary worker pools, capped WebView/Compose effects, reduced refresh when paused/hot, measure underruns/jitter and battery with the S24+ charging plus DAC attached.

Validation matrix to include in final implementation specification:
- Source/destination formats: 44.1/48/88.2/96/176.4/192/352.8/384k where hardware supports; integer16/24/32, float sources, mono/stereo as supported; exact bypass hashes; DSP changes honest.
- Consecutive same-format tracks keep stream; changed format reopens cleanly; crossfade excludes protected albums and loses exact label only in relevant processed interval; UI/native transition state stays synchronized.
- USB unplug/replug, loss/denial/fallback, fixed48k device, explicit/implicit feedback; measure endpoint behavior on real S24+ and DACs instead of inferring from UI.
- Lyrics: multiple tags, offsets, blank/instrumental lines, malformed files, word timing fallback, seeks/end-of-track/crossfade media identity, offline/provider timeout/429 and attribution.
- UI/dock: rotation, lock/unlock, app background, display off, night/privacy/accessibility, WebView lifecycle, low-power/thermal mode, no audio underrun increase.
- Library/downloads: migration, duplicate/version handling, 10k+ synthetic metadata scalability where reasonable, stale URI/token refresh, malformed headers, download pause/cancel/process death/out-of-space, pinned-cache protection.
- Build/release: existing native sanitizer suite, explicit Kotlin tests and lint, merged manifest, API36 behavior, every packaged .so plus AAB zip alignment and 16KB emulator/device test, licenses/attribution inventory.
